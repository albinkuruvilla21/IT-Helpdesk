# Acies Innovations IT Help — data model

> Generated by `/list-schemas` with the CSVs in `schemas/` (stage **G5**). The CSV is the column
> definition; this file says **why**, and holds what a CSV can't: volume, threshold strategy,
> archival, permissions, flows. Change both together.

Site: the project's SharePoint site, chosen by the importer in the import wizard (`ith_SharePointSite`). Nothing in code names it.
Every list's base `Title` column cannot be indexed from a schema; no screen filters on it server-side (search is local over the loaded collection).

## 2. Relationships

A reference stores the target's SharePoint item ID in an indexed Number column `<Target>Id`, plus a display value. Item IDs are not kept when a list is re-created on another site: moving data between sites means remapping these columns.

| From (list.column) | To (list, by item ID) | Display value kept in |
|---|---|---|
| `ITH_TicketComment.TicketId` | `ITH_Ticket` | `TicketTitle` |
| `ITH_TicketActivity.TicketId` | `ITH_Ticket` | `TicketTitle` |

Category, priority, status and assignee are stored as text copies of master-data values (L7), not references: renaming a value in a master list does not rewrite old tickets, which is the audit behaviour wanted.

## 3. Flows

| Flow | Owner (service account) | Trigger | Reads / writes | Failure behaviour | Verified on tenant |
|---|---|---|---|---|---|
| Notify requester - ticket created | 🔶 | Item created in `ITH_TicketActivity`, `EventType = Created` | Reads `ITH_Ticket`; sends mail | Flow run fails visibly; no retry beyond the default; nothing is written back | No |
| Notify technician - ticket assigned | 🔶 | Same, `EventType = Assigned` | Reads `ITH_Ticket`, `ITH_Technician`; sends mail | As above | No |
| Notify requester - ticket updated | 🔶 | Same, `EventType` in StatusChanged, Resolved, Comment | Reads `ITH_Ticket`; sends mail | As above | No |

## 4. Open points

| ID | Point |
|---|---|
| Q-23 | Comments and activity must be readable by the requester of the ticket, so their lists cannot use "own items only". The client can accept list-wide read, or ask for per-item permissions (a flow, out of scope). Baseline: list-wide read, app-filtered |
| Q-24 | Item-level "own items" on `ITH_Ticket` follows the item's creator. A ticket staff raise for someone else is created by staff, so that requester cannot read it through SharePoint. Baseline: accepted, as Q-21 already limits who can raise for others |
