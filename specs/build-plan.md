## 5. Flows

| Flow (display name) | Trigger | Does | Connection references | Environment variables | AC IDs |
|---|---|---|---|---|---|
| Notify requester - ticket created | SharePoint: item created in `ITH_TicketActivity`, condition `EventType = Created` | Reads the ticket, emails the requester its ID, subject and link | `ith_sharepoint`, `ith_office365outlook` | `ith_NotificationMailbox`, `ith_AppLink`, list and site | AC-ITH-32 |
| Notify technician - ticket assigned | Same trigger, `EventType = Assigned` | Emails the new assignee unless they made the change | same | same | AC-ITH-33 |
| Notify requester - ticket updated | Same trigger, `EventType` in StatusChanged, Resolved, Comment | Emails the requester with the new status or the comment author, unless they made the change | same | same | AC-ITH-34 |

The app writes the activity entry for every event; the flows react to it. This keeps the app free of mail logic and the trigger on one indexed list.

## 6. Build order

1. Tokens and `App` named formulas (G3 done); `colScheme`, role and master-data loads (`App.OnStart`).
2. The chrome: sidebar and header (with notifications and profile menus), on every screen.
3. `scrOverview` (start screen), then `scrTickets` (tables, filters, paging), then the overlay set (form, drawer, confirmation), `scrKnowledge`, `scrSettings`.
4. Lists (G5) before formulas bind to them (G8); mock data (`--mock`) until then (G6, G7).
5. Flows (G9) after the lists they read.
